# 어떤 정보를 수집하나요?

- 수집 대상: Microsoft Foundry, Azure 자체 호스팅 Agent, Azure Monitor·Log Analytics, 비용·보안 권고.

- 이 목록은 **구현된 읽기 수집 항목**입니다. 모든 고객 환경에서 모든 값이 나온다는 뜻은 아닙니다. 권한·API 응답·계측·관측 기간이 부족하면 값을 비워 두고 이유를 기록합니다. 진단 범위는 Azure와 Microsoft Foundry입니다.

## Agent 공통 정보

- **수집 시각**
  - 프로그램 필드: collected_at
  - 어디서 확인하나요?: 실제 수집 실행 시각, UTC
- **테넌트·구독·리소스 그룹**
  - 프로그램 필드: tenant_id, subscription_id, resource_group
  - 어디서 확인하나요?: Azure 구독·Resource Graph
- **플랫폼·호스팅**
  - 프로그램 필드: platform, hosting_type
  - 어디서 확인하나요?: Foundry 서비스/태그/이름 규약/수동 입력
- **Agent ID·이름·버전**
  - 프로그램 필드: agent_id, agent_name, agent_version
  - 어디서 확인하나요?: Foundry Agent/버전 목록 또는 LangChain 호스트
- **리소스 경로**
  - 프로그램 필드: resource_id
  - 어디서 확인하나요?: 해당 프로젝트·호스팅 리소스
- **담당·후원 조직**
  - 프로그램 필드: owner, sponsor
  - 어디서 확인하나요?: 고객 태그. 식별 가능한 값은 가명·마스킹
- **환경·비용센터 등 태그**
  - 프로그램 필드: tags
  - 어디서 확인하나요?: 리소스/프로젝트/Agent 메타데이터
- **탐지 근거**
  - 프로그램 필드: detection_confidence
  - 어디서 확인하나요?: 태그 확인 / 이름으로 추정한 후보 / 수동 등록
- **생성 시각**
  - 프로그램 필드: created_at
  - 어디서 확인하나요?: API가 제공한 생성 시각
- **배포 시각**
  - 프로그램 필드: deployed_at
  - 어디서 확인하나요?: 신뢰할 수 있는 배포 증거가 있을 때만. 생성 시각으로 대체하지 않음
- **누락 사유·증거 참조**
  - 프로그램 필드: field_status, evidence_refs
  - 어디서 확인하나요?: 필드별 자료 없음/권한 부족 및 마스킹 원본 파일

- 이름으로 추정한 LangChain 리소스는 확정 Agent가 아니라 후보입니다. 한 호스트에 여러 논리 Agent를 운영하는 고객은 별도 등록·계측으로 연결해야 합니다. 기본 수집기는 웹 앱 하나를 Agent 하나로 식별하므로 프로세스 내부의 Agent 개수를 추측하지 않습니다.

## 모델·도구·평가

- **모델 이름·버전**
  - 프로그램 필드·기록: model, model_version
  - 수집원·주의: 실제 모델 배포와 Agent의 배포명 연결
- **모델 리소스·비용 연결**
  - 프로그램 필드·기록: model_resource_id, cost_resource_ids
  - 수집원·주의: 계정·호스트·App Service 플랜 경로
- **도구 종류**
  - 프로그램 필드·기록: tools
  - 수집원·주의: Foundry 버전 정의. 앱 내부 Python 도구는 태그만으로 확정하지 않음
- **모델 배포 상세**
  - 프로그램 필드·기록: ModelDeployment
  - 수집원·주의: 이름·모델·버전·형식·SKU·용량·배포 상태·연결된 안전 정책명
- **평가 실행 이력**
  - 프로그램 필드·기록: EvaluationRun
  - 수집원·주의: 실행 ID·상태·프로젝트·Agent ID/버전·완료 시각·문항 전체/통과/실패/오류 수·근거
- **배포 전 평가 여부**
  - 프로그램 필드·기록: evaluated_before_deploy
  - 수집원·주의: 같은 Agent/버전의 평가 완료와 배포 시각을 비교. 하나라도 없으면 보류
- **안전 정책 연결**
  - 프로그램 필드·기록: guardrail_applied
  - 수집원·주의: 모델 배포의 정책 연결만 확인. 실제 차단 성능·조직 전체 가드레일 입증은 아님

- **평가 실행 이력이 있는 것**과 **운영 배포 전에 평가한 것**은 다릅니다. 메타데이터의 Agent 연결은 등록자가 제공한 연결 정보이며 서비스가 자동 보증한 배포 lineage가 아닙니다. 평가 목록을 읽으려면 프로젝트 데이터 평면의 추가 읽기 역할이 필요합니다.

## 사용량·비용

- **최근 30일 호출 수**
  - 프로그램 필드·기록: usage_30d.calls
  - 조건·한계: Azure Monitor 메트릭 또는 Agent ID가 있는 앱 로그
- **최근 30일 토큰 수**
  - 프로그램 필드·기록: usage_30d.tokens
  - 조건·한계: 입력·출력 토큰. 필드가 빠졌다고 0으로 채우지 않음
- **마지막 사용 시각**
  - 프로그램 필드·기록: last_used_at
  - 조건·한계: Agent에 연결된 관측 증거가 있을 때만
- **90일 호출·관측 시작**
  - 프로그램 필드·기록: calls_90d, usage_coverage_start
  - 조건·한계: 실제 데이터 보존·계측 기간 필요
- **최근 30일 Agent 비용·통화**
  - 프로그램 필드·기록: cost_30d, currency
  - 조건·한계: 리소스가 정확히 한 Agent에 연결될 때만 귀속
- **리소스별 청구 내역**
  - 프로그램 필드·기록: CostRecord
  - 조건·한계: 구독·리소스·금액·통화·사용일·증거
- **월별 비용 합계**
  - 프로그램 필드·기록: cost_monthly.csv
  - 조건·한계: 통화별 구분. 청구 반영 전 빈 결과는 0원 아님
- **비용 식별률**
  - 프로그램 필드·기록: OT-SY-19
  - 조건·한계: 확인한 AI 비용 중 Agent에 유일하게 연결되는 비용 비율

- 공유 모델·공유 플랜·모니터링 비용을 여러 Agent에 중복 배분하지 않습니다. 최근 사용이 보이지 않아도 90일 전체 관측이 없으면 장기 미사용으로 확정하지 않습니다. 로그 기반 사용량은 해당 워크스페이스의 데이터 읽기 권한과 Agent 계측이 필요합니다.

## 로그·보안·수집 신뢰도

- **진단 로그 설정·전송 대상**
  - 수집원: Azure Monitor diagnosticSettings
  - 무엇을 의미하나요?: 수집 범주 활성화·워크스페이스 연결
- **구독 Activity Log 전송·보관**
  - 수집원: 구독 진단 설정·워크스페이스
  - 무엇을 의미하나요?: 기본 Activity Log가 존재하는 것과 장기 보관 설정을 구분
- **워크스페이스 보존 기간**
  - 수집원: Log Analytics ARM 설정
  - 무엇을 의미하나요?: 일수. 고객 승인 범위 밖 중앙 워크스페이스는 추가 조회하지 않음
- **AI 연결 보안 권고**
  - 수집원: Defender for Cloud assessment
  - 무엇을 의미하나요?: 권고 ID·대상·심각도·상태. 빈 목록을 양호로 판단하지 않음
- **추가 권한·실패**
  - 수집원: Issue
  - 무엇을 의미하나요?: 실패한 구독/대상/API 구간·사유·추가 읽기 역할·원본 참조
- **전체/완료 구독**
  - 수집원: Collection
  - 무엇을 의미하나요?: 특정 구독 실패 때문에 전체 진단을 버리지 않음
- **인터뷰 차이**
  - 수집원: Finding
  - 무엇을 의미하나요?: 선택 입력한 인터뷰 수준과 실측 초안이 기준 이상 차이 나는지

## 수집하지 않는 것

- **키·비밀번호·토큰·연결문자열·앱 설정의 비밀값**
  - 이유: 진단에 불필요하며 조회 API도 호출하지 않음
- **실제 사용자 질문·답변·대화 본문**
  - 이유: Agent 메타데이터·집계 로그만 대상
- **리소스 변경·Agent 생성·추론·평가 실행**
  - 이유: 읽기 진단 범위 아님. 샘플 관리자 자동화에서만 별도 승인 실행
- **Entra/M365/Purview/Power Platform/Agent 365 제품 진단**
  - 이유: 다른 담당 범위
- **허가되지 않은 다른 구독·중앙 로그**
  - 이유: 승인 범위를 넘어 자동 조회·권한 확대하지 않음
