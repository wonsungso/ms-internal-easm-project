# Azure/Foundry 관점 추가 제안

- 현재 수집 대상: Microsoft Foundry, Azure 자체 호스팅 Agent, Azure Monitor, 비용·보안 권고.

- 아래는 기존 System Evidence 20개에 추가를 **검토할 후보**이며 현재 구현 대상이 아닙니다. 기존 코드에 몰래 편입하거나 기존 항목의 최종 점수로 사용하지 않습니다.

- **Foundry 프로젝트·Agent 인벤토리**
  - 제안 이유: 대상 구독에 분산된 Agent의 실제 규모와 플랫폼별 분포 확인
  - 검토할 읽기 증적: Resource Graph의 계정·프로젝트, Foundry Agent 목록, 수동 등록 목록
  - 확정 전에 확인할 사항: 관리 평면 프로젝트와 데이터 평면 Agent 구분, 클래식/신규 API, 중복 제거 키, Agent 버전과 배포 구분
- **콘텐츠 필터/가드레일 적용률**
  - 제안 이유: 모델 호출 경로별 안전 통제가 적용되는지 확인
  - 검토할 읽기 증적: 모델 배포의 정책 연결, Agent별 가드레일 구성, API Gateway 정책
  - 확정 전에 확인할 사항: 정책 연결만으로 실효성을 입증하지 못함; LangChain 경로의 우회 여부·사용자 정의 가드레일은 별도 증적 필요
- **트레이싱·모니터링 활성화율**
  - 제안 이유: 호출·토큰·오류·지연을 추적할 관측 기반 확인
  - 검토할 읽기 증적: 진단 설정, App Insights 연계, OpenTelemetry 설정 메타데이터
  - 확정 전에 확인할 사항: 연결문자열·프롬프트·응답 본문 수집 금지; 설정 존재와 실제 로그 유입 구분
- **네트워크 격리·Managed Identity·RBAC**
  - 제안 이유: 공용 노출과 비밀키 의존, 과다 권한을 별도 점검
  - 검토할 읽기 증적: publicNetworkAccess, Private Endpoint 상태, identity 및 Azure 역할 할당 메타데이터
  - 확정 전에 확인할 사항: Azure RBAC와 Entra API 권한을 혼동하지 않음; 네트워크 제한 시 수집기 접근 경로 필요
- **Azure Policy 준수율**
  - 제안 이유: 승인 모델·지역·보안 정책에 대한 구성 통제 확인
  - 검토할 읽기 증적: 정책 할당 및 Policy Insights 준수 상태
  - 확정 전에 확인할 사항: 비준수와 미평가 구분, 면제와 평가 지연 처리, 읽기 전용 조회만 허용
- **쿼터·예산 알림**
  - 제안 이유: 과소/과다 용량과 예산 초과를 사전 관리하는지 확인
  - 검토할 읽기 증적: 쿼터 사용량, 예산·알림 설정 메타데이터
  - 확정 전에 확인할 사항: 쿼터 조회 별도 역할, 비용 계약별 가시성, 예산 설정과 실제 발송·대응 이력 구분

## 제안 확정 절차

- 고객·평가 모델 담당자와 코드, 분모, 관측 기간, T1~T5 유형을 합의합니다.
- 적용 제품과 구독 범위를 확정하고 읽기 전용 API·역할을 공식 문서로 검증합니다.
- L1~L5와 N/A 기준을 별도 승인합니다. 기존 문서의 비율을 다른 지표에 재사용하지 않습니다.
- 합의 전에는 수치나 성숙도 점수를 산출하지 않습니다.
