# 읽기 권한 준비

- 수집 대상: Microsoft Foundry, Azure 자체 호스팅 Agent, Azure Monitor, 비용·보안 권고.
- 진단 계정
  - 대상 구독의 Reader가 기본입니다.
  - Owner·Contributor·User Access Administrator로 진단하지 않습니다.
  - 관리자 역할 할당 작업과 진단 수집은 별도 주체로 수행합니다.
- Reader로 먼저 확인하는 정보
  - 구독·리소스·Foundry 프로젝트·모델 배포.
  - 진단 로그 전송·워크스페이스 보존 설정.
  - 일반 Azure Monitor 메트릭.
- 실제 접근 거부가 있을 때 검토할 추가 역할
  - Foundry Agent·평가 목록: 지정 프로젝트의 사용자 지정 읽기 역할.
    - DataActions: agents/read, evaluations/read, assets/read.
    - agents/read는 서비스 권한 단위상 대화 읽기를 포함하지만 수집기는 대화 본문을 조회하지 않습니다.
    - assets/read는 프로젝트 asset 메타데이터 읽기도 허용합니다.
    - Foundry User처럼 키 조회·쓰기까지 허용하는 역할을 진단에 사용하지 않습니다.
  - Agent별 로그: 지정 워크스페이스의 Log Analytics Reader 및 Agent 계측.
  - 비용: 청구 계약·비용 공개 정책에 따라 Cost Management Reader.
  - 보안 권고: 고객 보안 정책에 따라 Security Reader와 기능 활성화 상태 확인.
  - 모니터링: 필요할 때 Monitoring Reader.
- 고객에게 요청할 내용
  - “대상 구독 Reader와 실제로 필요한 프로젝트·워크스페이스의 읽기 권한만 요청드립니다.”
  - “키 조회·Agent 변경·추론·평가 실행 권한은 진단 계정에 요청하지 않습니다.”
- 확인 결과
  - `output/permissions.json`과 `output/permissions.md`에서 확인합니다.
  - 접근 성공은 데이터 완전성·전체 관측 기간·조직 성숙도를 보장하지 않습니다.
  - 관리자는 상속·그룹·PIM 권한도 따로 확인합니다.
